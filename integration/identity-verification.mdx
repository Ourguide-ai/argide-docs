title: "Identity verification"
description: "Let the agent call your API on behalf of the signed-in user"
---

Identity verification proves to Argide who the user is, so the agent can call your API as that user — "show my orders", "cancel my subscription". Your backend mints a JWT, the widget passes it to Argide, and Argide forwards it to your API on every tool call. This is the token flow behind [JWT Forward](/integration/openapi-auth#jwt-forward).

<Info>
  If you only want the user's name on their conversations, you don't need any of this. See [User identification](/setup/user-identification) — it needs no backend and no token.
</Info>

## How it works

1. The user signs in to **your** app.
2. Your backend mints an Argide identity token: a JWT signed with your product's `ARGIDE_AUTH_SECRET`.
3. Your frontend calls `window.argide('identify', { token })`.
4. Argide verifies the token and links it to the user's widget session. Their conversations show as **Verified** in [Conversations](/conversations/inbox).
5. When the agent calls your API, Argide sends that token as `Authorization: Bearer <token>`.
6. Your API verifies it with the same secret and knows which user is asking.

<Info>
  This is not your app's session JWT. It's a separate token your backend mints only for Argide, so your app's own session token stays private.
</Info>

## 1. Get your secret

In the dashboard, open **Deploy** → **Backend Integration** and click **Copy secret** next to **ARGIDE_AUTH_SECRET**.

Add it to your backend environment:

```bash
ARGIDE_AUTH_SECRET=your_secret_here
```

<Warning>
  Never expose this secret in frontend code. Anyone who has it can mint tokens that impersonate your users.
</Warning>

## 2. Create a token endpoint

Add an endpoint, behind your own login, that returns a fresh token for the current user.

<CodeGroup>

```javascript Node.js (Express)
const jwt = require('jsonwebtoken');

app.get('/api/argide-token', authMiddleware, (req, res) => {
  const token = jwt.sign(
    {
      sub: String(req.user.id),
      email: req.user.email,
      name: req.user.name,
    },
    process.env.ARGIDE_AUTH_SECRET,
    { algorithm: 'HS256', expiresIn: '1h' }
  );
  res.json({ token });
});
```

```python Python (FastAPI)
import os
import time

import jwt
from fastapi import Request


@app.get("/api/argide-token")
async def argide_token(request: Request):
    user = request.state.user
    token = jwt.encode(
        {
            "sub": str(user.id),
            "exp": int(time.time()) + 3600,
            "email": user.email,
            "name": user.name,
        },
        os.environ["ARGIDE_AUTH_SECRET"],
        algorithm="HS256",
    )
    return {"token": token}
```

```python Python (Flask)
import os
import time

import jwt


@app.route("/api/argide-token")
@login_required
def argide_token():
    token = jwt.encode(
        {
            "sub": str(current_user.id),
            "exp": int(time.time()) + 3600,
            "email": current_user.email,
            "name": current_user.name,
        },
        os.environ["ARGIDE_AUTH_SECRET"],
        algorithm="HS256",
    )
    return {"token": token}
```

</CodeGroup>

### Token claims

| Claim | Type | Required | Description |
| --- | --- | --- | --- |
| `sub` | string | Yes | Your unique user ID. You can send it as `userId` or `user_id` instead. |
| `exp` | number | Yes | Expiry, as a Unix timestamp in seconds. |
| `email` | string | No | The user's email. |
| `name` | string | No | The user's display name. |

- Sign with `HS256`. Other algorithms are rejected.
- The user ID must be a **string**. A numeric ID is ignored, and the token is rejected for having no user. Convert it with `String(id)` or `str(id)`.
- If you send more than one ID claim, Argide uses the first it finds, in the order `sub`, `userId`, `user_id`.
- A token without `exp`, or one that has already expired, is rejected.

## 3. Identify in your frontend

```javascript Script tag
async function identifyToArgide() {
  try {
    const res = await fetch('/api/argide-token');
    if (!res.ok) throw new Error(`Token request failed: ${res.status}`);
    const { token } = await res.json();
    window.argide('identify', { token, name: currentUser.name });
  } catch (err) {
    console.error('Argide identify failed', err);
  }
}

identifyToArgide();
```

`identify` takes the `token` and an optional `name`. A `name` you pass here takes priority over the token's `name` claim.

Call `identify` on every page load where the user is signed in, not only right after login. The token is tied to the widget's session in this browser, so a new browser, a new device, or cleared site data needs a fresh one.

<Tip>
  If `identify` might run before the widget script has loaded, queue it instead: `window.argide.push(['identify', { token }])`. This needs the `window.argide = window.argide || [];` line from the install snippet. The widget runs queued commands as soon as it loads.
</Tip>

### Keep the token fresh

Re-mint the token before `exp` passes. Once the stored token expires, Argide stops sending requests to your API for that user — the agent asks them to sign in again instead. With a one-hour token, refresh every 50 minutes:

```javascript Script tag
setInterval(identifyToArgide, 50 * 60 * 1000);
```

## 4. Enable JWT Forward

Argide only stores the token when your product's API authentication is set to **JWT Forward**.

1. Open **Tools** → **Server Side**.
2. Set **Authentication** to **JWT Forward** and click **Save Configuration**.
3. Verify the token in your API with the same `ARGIDE_AUTH_SECRET`. See [Verify the token in your API](/integration/openapi-auth#verify-the-token-in-your-api).

<Warning>
  Without **JWT Forward** selected, `identify` succeeds but stores nothing. This is the most common reason identity appears to do nothing.
</Warning>

## 5. Handle sign-out and user switches

Call one of the reset commands when the user signs out. The widget doesn't detect your app's sign-out on its own.

| Command | Token | Conversation | Use when |
| --- | --- | --- | --- |
| `window.argide('resetAndClearSession')` | Revoked | Cleared — the widget starts a fresh, anonymous session | The user signs out, especially on shared devices |
| `window.argide('resetAndPreserveSession')` | Revoked | Kept on screen | You want the conversation to stay visible after sign-out |

Both commands also clear `user_id`, `name`, `email`, and custom attributes from `window.ArgideSettings`.

If a different person signs in on the same browser, you don't have to reset first. When `identify` receives a token for a different user ID than the last one, the widget starts a new session automatically: it clears the previous conversation and revokes the previous user's token before storing the new one.

## Troubleshooting

When `identify` fails, the widget logs a warning to the browser console that starts with `[Argide-B2B]`.

| Console message | Fix |
| --- | --- |
| `JWT must include an exp claim` | Add an `exp` claim. |
| `JWT must identify an end user via sub, userId, or user_id` | Add a user ID claim, as a string. |
| `Invalid token: …` | The token is expired, isn't signed with `HS256`, or isn't signed with this product's `ARGIDE_AUTH_SECRET`. |
| `identify: token is required` | You called `identify` without a `token`. |

If there's no warning but your API still gets requests without an `Authorization` header, check that **Authentication** is set to **JWT Forward**.

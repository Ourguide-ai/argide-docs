---
title: "Running Tasks"
description: "Start, monitor, cancel, and recover agent tasks"
---

A task is one goal handed to the agent. This page covers the full lifecycle: starting a task, the one-goal-at-a-time rule, getting the result, answering a task that waits for the user, cancelling, and what happens when the agent navigates the page out from under itself.

## Start a task

```ts
const { taskId } = await ArgideAgent.do({ goal: "cancel my subscription" });
```

`do()` resolves as soon as the task exists — not when it finishes. It also waits internally for `init` and the claim to complete, so you can call it right after `init` with no readiness check.

## Pass the conversation

When the goal comes from your chatbot, pass its conversation too. The agent then understands follow-ups like "now schedule **it** weekly".

```ts
const { taskId } = await ArgideAgent.do({
  goal: "Schedule the Q3 report weekly",
  messages: conversation.messages, // as your stack holds them
});
```

Pass the messages in your stack's own format: OpenAI, Anthropic, Gemini, the Vercel AI SDK, and A2A all work. Only user and assistant text leaves the page. The agent acts only on `goal`, so put everything it must do there.

## One goal at a time

Each session runs at most one task. A `do()` while a task is running rejects with `409 SESSION_BUSY`. Wait for the task to settle, or `cancel()` it first.

A task that is waiting for the user (`needs_input`) doesn't hold the session: `do()` starts a new task. To continue the waiting task, call `resume()`.

## Get the result

```ts
ArgideAgent.onActivity((activity) => {
  if (activity.kind !== "task") return;
  // { kind: "task", taskId, status, summary, needs }
  showResult(activity);
});
```

When the task finishes, or stops to wait for the user, the SDK sends a `task` event. `status` is one of `needs_input`, `completed`, `failed`, or `cancelled`; `summary` is a string or `null`. The SDK reads the task from Argide itself, after a page reload too, so you don't poll. A result that arrives before any listener is subscribed is handed to the first listener that subscribes.

A `failed` event with `summary: null` can also mean this tab can no longer reach the task. To read a task yourself, call `check()`.

## When the agent needs the user

A task can pause to wait for the user: the agent needs a value only they can give, or they must do something on the page first, such as logging in. The SDK then sends a `task` event with `status: "needs_input"`, and `summary` says what the agent needs. Answer with `resume()`, which continues the same task.

```ts
ArgideAgent.onActivity((activity) => {
  if (activity.kind === "task" && activity.status === "needs_input") {
    // Show activity.summary. For needs.kind "input", build a form from activity.needs.fields.
    showQuestion(activity);
  }
});

// When the user answers. Here the task asked for one field, named "Role":
await ArgideAgent.resume({ inputs: { Role: "admin" } });
// For needs.kind "user_action", once the user has done it:
await ArgideAgent.resume({ message: "Done" });
```

`resume()`, `check()`, and `cancel()` act on the current task when you pass no `taskId`.

For `needs.kind === "input"`, send a value for every field in `needs.fields`, keyed by its `name`:

| Field `type` | Value |
| ------------ | ----- |
| `text` | A string |
| `options` | A string from `options`, or the user's own. An array of strings when `allowMultiple` is set. |
| `date` | A `YYYY-MM-DD` string |
| `checkbox` | `true` or `false` |

The SDK announces a question once, even after a page load. If your page can reload while a task waits, keep the question in your own state, such as `sessionStorage`, until you call `resume()`.

## End a task early

```ts
await ArgideAgent.cancel();
```

Cancelling also sends the task's `cancelled` event.

## Handle errors

`check()`, `cancel()`, and `resume()` reject on any non-2xx response, with the HTTP status on the error's `status`:

```ts
try {
  await ArgideAgent.cancel();
} catch (err) {
  const status = (err as { status?: number }).status;
  if (status === 404) {
    // unknown task, or a task belonging to another session
  } else if (status === 409) {
    // the task is already terminal
  }
}
```

## Watch progress

Three signals, three jobs:

| Signal | What it tells you | Use it for |
| ------ | ----------------- | ---------- |
| `onActivity(cb)` | The task's result (`task`), plus ephemeral, per-tab events as the agent works: `tool-start`, `tool-end`, `idle` | Showing the result, and a live "agent is working" UI |
| `onStateChange` (an `init` option) | Facade lifecycle: `"starting" \| "ready" \| "error" \| "stopped"` | Enabling or disabling your entry points |
| `check()` | A task's status, read on demand | Checking a task yourself |

```ts
const off = ArgideAgent.onActivity((activity) => {
  if (activity.kind === "task") return; // results: see Get the result
  setWorking(activity.kind !== "idle");
});
// later, to unsubscribe: off()
```

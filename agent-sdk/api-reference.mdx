```ts
import { ArgideAgent, startAgentRuntime } from "@ourguide-ai/agent";
```

`ArgideAgent` is a facade that owns one runtime per page — it is what most integrations use. [`startAgentRuntime`](#startagentruntime) is the lower-level primitive it wraps.

## ArgideAgent.init(options)

Initializes the page's runtime. Idempotent and safe under React StrictMode — call it from anywhere, any number of times. On the server (SSR) it warns and does nothing; no session is minted until it runs in a browser.

| Option | Type | Required | Description |
| ------ | ---- | -------- | ----------- |
| `apiUrl` | `string` | Yes | Your Argide API host, e.g. `https://api.argide.ai` |
| `productId` | `string` | Yes | The product this page belongs to |
| `claim` | `({ sessionId, pairingCode }) => Promise<void>` | No | Called only when a session is freshly minted — never on recovery. Exchange the pair for a claim via your server. Omit to claim through [your own channel](/agent-sdk/claiming-sessions#custom-path-your-own-channel). |
| `onStateChange` | `(state) => void` | No | Reports the facade lifecycle: `"starting" \| "ready" \| "error" \| "stopped"` |
| `assetOrigin` | `string` | Yes | Set to `https://dashboard.argide.ai` to let the agent take screenshots. |

## ArgideAgent.do(\{ goal, messages \})

Starts a task, or rejoins the running one.

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `goal` | `string` | Yes | What the agent should do. |
| `messages` | `object[]` | No | Your chatbot's conversation, in your stack's own message format. Only user and assistant text is sent. See [Pass the conversation](/agent-sdk/running-tasks#pass-the-conversation). |

- Returns `Promise<{ taskId: string }>` — resolves as soon as the task exists, not when it finishes. Waits internally for init and the claim first.
- Rejects with `409 SESSION_BUSY` when called with a *different* goal while a task is running.
- Called with the *same* goal as the running task, it resolves with the same `taskId` (rejoin).

## ArgideAgent.check(\{ taskId \})

Reads a task's status from Argide: the current task, or the one you pass.

- Returns `Promise<{ taskId, status, summary, needs }>`. `status` is one of `running`, `needs_input`, `completed`, `failed`, or `cancelled`; `summary` is a string or `null`. `needs` is set only while `status` is `needs_input` — see [When the agent needs the user](/agent-sdk/running-tasks#when-the-agent-needs-the-user).
- `taskId` is optional. Without it, `check()` reads the current task, and rejects when there is none.
- Rejects on any non-2xx, including `404` for a task that is unknown or belongs to another session.

## ArgideAgent.resume(\{ taskId, inputs \| message \})

Continues a task that is waiting for the user, or sends a follow-up to a completed one. The task keeps its `taskId`.

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `taskId` | `string` | No | The task to continue. Defaults to the current task. |
| `inputs` | `Record<string, string \| string[] \| boolean>` | One of `inputs` or `message` | Answers `needs.kind === "input"`: a value for every field, keyed by its `name`. See [field values](/agent-sdk/running-tasks#when-the-agent-needs-the-user). |
| `message` | `string` | One of `inputs` or `message` | Answers `needs.kind === "user_action"`, or follows up on a `completed` task. |

- Returns `Promise<{ taskId: string }>` — resolves once the server accepts the answer, not when the task finishes.
- Rejects with `400` when the answer doesn't match what the task is waiting for, `404` for an unknown or foreign task, and `409` when the task failed or was cancelled, or another task is running.

## ArgideAgent.cancel(\{ taskId \})

Ends the task early: the current task, or the one you pass.

- The returned promise resolves with the same `{ taskId, status, summary }` outcome shape as `check()`.
- For the current task, `onActivity` also gets its `cancelled` event.
- Rejects on any non-2xx, including `404` (unknown or foreign task) and `409` (task already terminal).

## ArgideAgent.onActivity(callback)

Subscribes to the task's results and to live activity. Returns an unsubscribe function.

```ts
const off = ArgideAgent.onActivity((activity) => {
  // { kind: "tool-start" | "tool-end" | "idle" | "task", ... }
});
// later, to unsubscribe: off()
```

A `task` event is the task's result: `{ kind: "task", taskId, status, summary, needs }`, with `status` one of `needs_input`, `completed`, `failed`, or `cancelled`. The SDK reads it from Argide when the task finishes or waits for the user, after a page reload too. `tool-start`, `tool-end`, and `idle` are ephemeral and per-tab.

## ArgideAgent.session()

Returns `Promise<{ sessionId, pairingCode, recovered }>` for claiming through your own channel.

Claim only when `recovered` is `false` — a recovered session is already claimed, and re-claiming returns `409 ALREADY_CLAIMED`. See [Claiming Sessions](/agent-sdk/claiming-sessions).

## ArgideAgent.stop()

Tears down and resets the runtime. The next `init()` starts fresh. Normal pages never call this — the runtime is designed to live as long as the tab.

- Local teardown only: it leaves a running task alive server-side. Use `cancel()` to end the task.

## Errors

| Error | Status | Surfaces from | What it means |
| ----- | ------ | ------------- | ------------- |
| `SESSION_BUSY` | 409 | `do()`, `resume()` | A different task is still running. Wait or `cancel()` first. |
| `ALREADY_CLAIMED` | 409 | the claim endpoint | The session was already claimed. Reserved as the stolen-pairing-code signal — do not retry. |
| `INPUTS_REQUIRED` | 400 | `resume()` | The task is waiting for `inputs`, and a field is missing or has the wrong type, or a `message` was sent. |
| `MESSAGE_REQUIRED` | 400 | `resume()` | The task takes a `message` (it is waiting for a user action, or is `completed`), and `inputs` were sent. |
| Not found | 404 | `check()`, `cancel()`, `resume()` | Unknown `taskId`, or a task belonging to another session. |
| Conflict | 409 | `cancel()` | The task is already terminal. |
| Conflict | 409 | `resume()` | The task failed or was cancelled. Start a new one with `do()`. |

These codes describe server-side behavior. When Argide refuses a request, `do()`, `check()`, `cancel()`, and `resume()` reject with an `Error` whose `status` is the HTTP status (e.g. `409`); the message says the same (`agent task create failed: HTTP 409`). The codes themselves, such as `SESSION_BUSY`, aren't exposed on the error.

## startAgentRuntime

`ArgideAgent` owns one runtime per page. Drop down to the primitive it wraps when you need more than one product on a page, or you want to manage the lifecycle yourself:

```ts
import { startAgentRuntime } from "@ourguide-ai/agent";

const argide = await startAgentRuntime({ apiUrl, productId, assetOrigin });
// argide.{ sessionId, pairingCode, recovered, do, resume, check, cancel, onActivity, stop }
```

At this level the claim-on-recovered rule and concurrent-start guarding are your responsibility: check `recovered` before claiming, and guard against starting two runtimes concurrently yourself. The runtime doesn't follow the task for you either: `check()`, `cancel()`, and `resume()` need a `taskId`, and `onActivity` sends no `task` events.

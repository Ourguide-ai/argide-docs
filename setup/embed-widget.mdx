One script tag loads Argide on your site. It shows as a floating chat widget or as a copilot sidebar, depending on the mode you pick in the dashboard. You control it from your own code with `window.argide` commands.

## Before you start

The widget only loads on your product's **Website** and its subdomains. Set it in **Settings** → **Products**. Until a Website is set, the widget loads nowhere, and **Deploy** → **Install** shows a warning saying so.

| Website in the dashboard | Loads on | Doesn't load on |
| --- | --- | --- |
| `https://example.com` | `example.com`, `www.example.com`, `app.example.com` | `notexample.com`, `http://example.com`, `localhost` |
| `https://www.example.com` | Same as above. A leading `www.` is ignored. | Same as above |
| `http://example.com` | `http://` and `https://` on `example.com` and its subdomains | Other domains |
| `https://myapp.vercel.app` | `myapp.vercel.app`, `www.myapp.vercel.app` | Any other `*.vercel.app` site, including preview deployments |

On shared hosting domains — `vercel.app`, `netlify.app`, `pages.dev`, `github.io`, `myshopify.com`, `web.app`, `firebaseapp.com`, and `onrender.com` — subdomains are other people's sites. There, only the exact host and its `www.` form match.

<Warning>
  There is no exception for `localhost`, staging, or preview URLs. On a page outside your Website, the Argide bundle request returns `403` and nothing renders. To test somewhere else, use a separate product whose Website is that origin, such as `http://localhost:3000`. The port must match.
</Warning>

## Add the script

Open **Deploy** → **Install** and copy the snippet under **Add the script**. It already contains your Product ID. Paste it just before the closing `</body>` tag on every page where the agent should appear.

<CodeGroup>

```html HTML
<script>window.argide = window.argide || [];</script>
<script
  src="https://dashboard.argide.ai/argide-b2b.iife.js"
  data-product-id="YOUR_PRODUCT_ID"
  data-api-url="https://api.argide.ai"
></script>
```

```tsx Next.js — app/layout.tsx
import Script from "next/script";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Script id="argide-queue" strategy="beforeInteractive">
          {"window.argide = window.argide || [];"}
        </Script>
        <Script
          src="https://dashboard.argide.ai/argide-b2b.iife.js"
          data-product-id="YOUR_PRODUCT_ID"
          data-api-url="https://api.argide.ai"
          strategy="afterInteractive"
        />
      </body>
    </html>
  );
}
```

</CodeGroup>

The first line creates a queue, so your code can send commands before Argide finishes loading. See [Send commands before the widget loads](#send-commands-before-the-widget-loads).

Your Product ID is also listed on the product's card in **Settings** → **Products**.

### Script attributes

| Attribute | Required | Description |
| --- | --- | --- |
| `data-product-id` | Yes | Your Product ID. Without it, nothing loads. |
| `data-api-url` | No | The Argide API. Defaults to `https://api.argide.ai`. |
| `data-mode` | No | `widget` or `copilot`. Forces a mode and ignores the dashboard setting. |
| `data-visibility` | No | Set to `"false"` to load the widget hidden. See [Visibility](/agent/visibility). |
| `data-user-id` | No | Your ID for the signed-in user. See [User identification](/setup/user-identification). |
| `data-name` | No | The user's name. |
| `data-email` | No | The user's email. |

The agent's name, welcome message, and look come from the dashboard, not from the script tag. See [Identity and instructions](/agent/identity-instructions) and [Mode and design](/agent/mode-design).

## Choose widget or copilot

| Mode | Dashboard label | What users see |
| --- | --- | --- |
| Widget | **Regular** | A chat bubble in the bottom corner that expands into a chat panel |
| Copilot | **Copilot** | A full-height sidebar beside your app, on the left or right |

Pick the mode under **Choose how it appears** on **Deploy** → **Install**. It saves as soon as you click. You can also change it, along with the copilot's side, in **Agent** → **Mode**. The script tag stays the same in both modes, and the change applies on the next page load.

On screens 768px wide or narrower, copilot mode falls back to the widget layout.

To pin a mode in code, for example to run your own A/B test, add `data-mode="widget"` or `data-mode="copilot"` to the script tag. A forced mode overrides the dashboard setting on that page.

## Content Security Policy

If your Content Security Policy uses nonces, add your nonce to both `<script>` tags in the snippet. The loader passes its nonce on to the Argide bundle it injects.

```html
<script nonce="YOUR_NONCE">window.argide = window.argide || [];</script>
<script
  nonce="YOUR_NONCE"
  src="https://dashboard.argide.ai/argide-b2b.iife.js"
  data-product-id="YOUR_PRODUCT_ID"
  data-api-url="https://api.argide.ai"
></script>
```

Your policy must also allow scripts from `https://dashboard.argide.ai` and requests to `https://api.argide.ai`.

## Control the widget with `window.argide`

Once Argide has loaded, `window.argide` is a function that takes a command name and an optional payload:

```javascript
window.argide('update', { name: 'Ada Lovelace' });
```

| Command | Payload | What it does |
| --- | --- | --- |
| `update` | Object | Sets user attributes (`user_id`, `name`, `email`, and custom keys) and `visibility`. See [User identification](/setup/user-identification). |
| `identify` | `{ token, name? }` | Sends a signed JWT so the agent can call your API as this user. See [Identity verification](/integration/identity-verification). |
| `resetAndClearSession` | None | Clears the user's identity and starts a new, anonymous session with an empty conversation. Call it on logout. |
| `resetAndPreserveSession` | None | Clears the user's identity and revokes their JWT, but keeps the current conversation. |
| `setNavigate` | Function `(path) => void` | Gives the widget your single-page app's router, so the agent navigates without a full page reload. Widget mode only. See [Page navigation](/agent/page-navigation). |

<Note>
  `resetUser` still works as an alias for `resetAndPreserveSession`, but it is deprecated and logs a console warning.
</Note>

### Send commands before the widget loads

Argide loads asynchronously, so your code may run before `window.argide` is a function. Until then, `window.argide` is the queue array the snippet created. Push `[command, payload]` pairs onto it, and Argide runs them in order once it loads:

```javascript
window.argide = window.argide || [];
window.argide.push(['update', { user_id: 'usr_8241', name: 'Ada Lovelace' }]);
```

After Argide loads, `window.argide` is replaced by the function, and `push` no longer exists. If your code can run at either moment, use a small helper that handles both:

```javascript
function sendArgideCommand(command, payload) {
  if (typeof window.argide === 'function') {
    window.argide(command, payload);
  } else {
    (window.argide = window.argide || []).push([command, payload]);
  }
}

sendArgideCommand('update', { user_id: 'usr_8241', name: 'Ada Lovelace' });
```

Every command can be queued except `setNavigate`. Call it only once `window.argide` is a function:

```javascript
function whenArgideReady(callback, attempts = 100) {
  if (typeof window.argide === 'function') return callback();
  if (attempts > 0) setTimeout(() => whenArgideReady(callback, attempts - 1), 100);
}

whenArgideReady(() => {
  window.argide('setNavigate', (path) => router.push(path));
});
```

Here `router` is your app's router. The helper stops checking after 10 seconds, so it doesn't poll forever if Argide fails to load.

## Troubleshooting

Argide logs to the browser console with an `[Argide-B2B]` prefix. Start there.

| Symptom | Cause and fix |
| --- | --- |
| Nothing renders, the network tab shows `403` for `argide-b2b-widget.iife.js` or `argide-b2b-copilot.iife.js`, and the console shows `loader: failed to load Argide` | The page's domain isn't your Website or one of its subdomains. Fix the **Website URL** in **Settings** → **Products**. See [Before you start](#before-you-start). |
| Your domain is listed under **Verify installation**, but no widget appears | Same cause. Argide records the domain before it checks it against your Website. |
| Nothing renders on `localhost` or a preview deployment | Expected. Those origins don't match your Website. |
| Nothing renders on any page | **Deploy** → **Install** shows a warning if no Website is set. Set one in **Settings** → **Products**. |
| `loader: data-product-id is required` | Add `data-product-id` to the script tag. |
| `loader: could not find script element` | Keep the original script tag. Its `src` must still contain `argide-b2b` and it must carry `data-product-id`. |
| `loader: failed to fetch config` | The loader couldn't reach the API, so it fell back to widget mode, or to your `data-mode` if set. Check `data-api-url`. |
| `window.argide is not a function` | Your code ran before Argide loaded. Queue the command, or use the helper above. |
| `window.argide.push is not a function` | Your code ran after Argide loaded. Call `window.argide(...)` directly, or use the helper above. |
| The mode doesn't match the dashboard | A `data-mode` attribute is forcing it. Remove it to follow the dashboard. |
| Copilot shows as a chat bubble on a phone | Expected. Copilot falls back to the widget layout at 768px wide or narrower. |
| The widget doesn't show, but no errors appear | Check for `data-visibility="false"` or an `update` call with `visibility: false`. See [Visibility](/agent/visibility). |
| `ArgideSettings update failed` | Argide rejected the user attributes, for example because `email` isn't a valid address. See [User identification](/setup/user-identification). |

title: "Page navigation"
description: "Give the agent a map of your app so it can take users to the right page"
---

Page navigation lets the agent move a user to another page in your app. When someone asks "where do I change my billing details?", the agent can open the billing page instead of describing how to get there.

The agent only navigates to routes you've saved. Each route is a path plus a description of what the page is for, and the agent picks a route by matching the user's request against those descriptions. Manage them in **Tools** → **Page Navigation**. You need the [Admin role](/organization/members) to save routes.

## Add routes

There are three ways to fill in your routes. You can mix them.

### From a website crawl

The fastest start is to crawl your app. In **Knowledge Base**, run a crawl in the **Website** section (see [Website & help center](/knowledge-base/website)). Argide finds your pages from your site map, your app's code and the pages it crawls, and can open your app in a browser to look further.

Discovered routes don't go live on their own. They wait in a **Review discovered routes** panel, which appears both under the crawl form and at the top of **Tools** → **Page Navigation**.

<Steps>
  <Step title="Review the changes">
    Each route is tagged so you can see what this crawl changed:

    | Tag | Meaning |
    | --- | ------- |
    | **New** | Found for the first time. |
    | **Changed** | Already live, with a new name or description. The old description is shown struck through. |
    | **Unchanged** | Already live and the same. Hidden by default; click **Show N unchanged** to see them. |
    | **Not seen this time** | Live, but this crawl didn't find it. |
    | **Yours** | A route you added by hand. It's always kept. |

    The **Found by** column shows where a route came from, such as **site map**, **app code**, **crawled page** or **browser**. Hover it to see how confident the crawl is in that route.
  </Step>
  <Step title="Edit or skip routes">
    Edit the **Name** or **Description** of any new or changed route. Click the trash icon to leave a route out of this save, and the restore icon to bring it back.
  </Step>
  <Step title="Decide what to remove">
    Routes marked **Not seen this time** stay live unless you tick **Remove** on them. A crawl can miss pages it couldn't reach, so nothing is removed for you.
  </Step>
  <Step title="Save">
    Click **Save routes**. The routes go live for the agent right away.
  </Step>
</Steps>

Re-crawl whenever your app changes. Each crawl produces a new review, and your hand-added routes are never touched.

#### Routes with a workspace in the URL

If your app puts a customer's workspace or account name in the URL, such as `/acme/settings/billing`, the crawl replaces that part with `:workspaceSlug`, giving `/:workspaceSlug/settings/billing`. That way one route works for every customer, not just the account you crawled with. The review panel shows the original URL from your crawl under each templated path.

When a user asks to go somewhere, the agent fills in `:workspaceSlug` from the URL that user is on right now. If they aren't inside a workspace, for example on your login page, the route can't be filled in and the agent doesn't navigate.

### Paste a list with Quick add

If your routes are defined in code, let a coding agent list them for you.

<Steps>
  <Step title="Copy the prompt">
    Under **Quick add**, copy the **Prompt for your AI coder**.
  </Step>
  <Step title="Run it against your codebase">
    Paste it into Cursor, Claude Code, or any coding agent that can read your repository. It returns a JSON array of routes.
  </Step>
  <Step title="Import">
    Paste the output into the **Quick add** box and click **Import**.
  </Step>
  <Step title="Save">
    Check the rows in the table, then click **Save routes**.
  </Step>
</Steps>

**Import** accepts JSON or CSV:

<CodeGroup>

```json JSON
[
  { "name": "Dashboard", "path": "/dashboard", "description": "Overview of account activity and key metrics." },
  { "name": "Billing", "path": "/settings/billing", "description": "Manage payment methods and view invoices." }
]
```

```text CSV
name, path, description
Dashboard, /dashboard, Overview of account activity and key metrics.
Billing, /settings/billing, Manage payment methods and view invoices.
```

</CodeGroup>

JSON can also be an object with a `routes` array. In CSV, a header line is optional, but if you include one it must start with `name,`. Without a header you can drop the name column (`path, description`). If a description contains commas, keep the name column so the line is read correctly.

<Warning>
  **Import** replaces every row in the table with the imported routes, and **Save routes** saves exactly what's in the table. Any live route that isn't in your import is removed when you save. To add to existing routes, include them in the import or add the new ones by hand.
</Warning>

### Add routes by hand

Under **Or add routes manually**, click **Add route**, fill in the row, and click **Save routes**. Click the trash icon on a row to delete it. Saving replaces your whole route list with the rows in the table.

## Route fields

| Field | Required | What it's for |
| ----- | -------- | ------------- |
| **Name** | No | A short label, such as `Billing`. |
| **Path** | Yes | The URL path. It must start with `/`, for example `/settings/billing`. |
| **Description** | Yes | What the user can do on the page. The agent matches requests against this, so it matters most. |

A path can contain dynamic segments, written `:name` or `[name]`, for example `/orders/:orderId`. The agent fills them in from what the user asked for, such as an order number they mentioned. If it can't fill every segment, it doesn't navigate.

Write descriptions the way a user would ask. "Manage payment methods, download invoices, and change your plan" works better than "Billing".

## How the agent navigates

When a user wants to go somewhere, the agent describes the destination in plain words, such as "billing settings", and Argide matches that against your route descriptions. If a route is a good enough match, the widget moves the user there. If none is, the agent doesn't navigate.

The chat shows the progress: **Finding the right page...**, then **Navigated to** the path, **No matching page found**, or **Invalid route** when a dynamic segment couldn't be filled in.

Navigating to a saved route never asks the user for approval. When [in-page actions](/agent/in-page-actions) are on, the agent uses page navigation only when the user wants to go somewhere, and uses in-page actions for requests like "submit the form".

## Use your app's router

To move the user, the widget tries these in order and stops at the first one that works:

1. The function you registered with `setNavigate`, if any.
2. Clicking a link on the current page that points to the same path.
3. A Next.js or Nuxt router it detects on the page.
4. Updating the URL with the browser's History API and firing a `popstate` event.
5. A full page load.

Most single-page apps work without any code. Register your own function with `setNavigate` when your router doesn't react to step 4, or when you want navigation to go through your own logic. The function receives the path to open:

```js
function registerArgideNavigate(navigate, attempts = 50) {
  if (typeof window.argide === "function") {
    window.argide("setNavigate", navigate);
  } else if (attempts > 0) {
    setTimeout(() => registerArgideNavigate(navigate, attempts - 1), 200);
  }
}
```

Call it where your router is in scope, and pass your router's navigation call. For example, with a router that has a `push` method:

```js
registerArgideNavigate((path) => router.push(path));
```

`setNavigate` only works once the widget has loaded. Unlike other commands, it can't be queued with `window.argide.push(...)` before then, which is why the example waits for `window.argide` to become a function.

<Note>
  `setNavigate` applies in widget mode only. In copilot mode it has no effect, and the agent always uses the fallback order above.
</Note>

Your function only controls how the move happens. Which page the agent picks still comes from the routes you saved.
